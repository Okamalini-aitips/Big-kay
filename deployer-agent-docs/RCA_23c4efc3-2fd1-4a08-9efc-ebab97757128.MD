# RCA — Deploy failed at `pull_source` (run 23c4efc3-2fd1-4a08-9efc-ebab97757128)

## App
- Deployment: `soccer-picks-bot`
- Template: `expo_mongo_base_image_eas` (Expo / EAS)
- Type: initial deploy

## What failed
The very first pipeline step, `pull_source`, failed while preparing the build context:

```
prepare build context: read envs: read env file frontend/.env:
open /tmp/agent-env-.../app/frontend/.env: no such file or directory (PathError)
```

The step reached the "read envs" phase, tried to open `frontend/.env`, and the file was not present in the pulled source tree.

## Root cause
The Expo/EAS deployer requires a `frontend/.env` file. During `pull_source` the deployer reads `frontend/.env` (this is where `EXPO_PUBLIC_BACKEND_URL` / the preview `.preview.emergentagent.com` URL lives — the deployer later `sed`-swaps that preview URL for the production backend URL when building the JS bundle). The file is missing from the app's source, so context preparation aborts before anything is built.

This is NOT an infra blip and NOT a manifest problem — a retry will fail identically because the file genuinely does not exist. It is a source-level gap.

## Note
Because `pull_source` failed, there is no source archive for this run, so I could not spawn an eph sandbox to reproduce. Diagnosis is from the pipeline error directly (which is unambiguous: `PathError: no such file or directory` on `app/frontend/.env`).

## Fix (for E1 — apply in the preview/source environment)
1. Create `frontend/.env` in the app source.
2. It must contain the frontend backend URL variable that the app reads, pointing at the current preview backend URL, e.g.:
   ```
   EXPO_PUBLIC_BACKEND_URL=https://repo-to-web-12.preview.emergentagent.com
   ```
   (Use the same variable name the app's frontend code actually reads. The value must be the preview URL — the deployer rewrites it to the production backend URL at build time. Do NOT hardcode the URL anywhere other than `frontend/.env`.)
3. Confirm the file is not excluded by `.gitignore`/`.dockerignore` in a way that would strip it from the pulled source.
4. Re-trigger the deploy.

Once `frontend/.env` exists in the source, `pull_source` will proceed.
