# RCA — soccer-picks-bot deploy failure (run b55041c7-45df-4f9a-9606-7a857e16b4d5)

## Summary
The `frontend/.env` fix worked — `pull_source` passed on this run. The deploy now fails one step later, in the **EAS OTA (`eas-update`) lane** of the Cloud Build (build step #7). The backend docker-build lane succeeded.

## Exact error
```
Step #7 - "eas-update": [EAS_LOG] Checking for dynamic config files...
Step #7 - "eas-update": [EAS_LOG] ERROR: No app.json, app.config.js, or app.config.ts found!
ERROR: build step 7 "...eas-builder-base:2026080502" failed: step exited with non-zero status: 1
```

## Root cause — template vs source mismatch
This deployment runs the Expo EAS template `expo_mongo_base_image_eas`. Its `eas-update` step (baked into the deployer binary) requires an Expo config file (`app.json` / `app.config.js` / `app.config.ts`) and an Expo/React-Native project to Metro-bundle and publish. **The source has no Expo project at all.**

Verified in eph sandbox against this run's source (`/app/scratch`):
- `frontend/` contains ONLY: `.env`, `package.json`, `package-lock.json`, `yarn.lock`. No `app.json`/`app.config.*`, no `expo` dependency. `frontend/package.json` is a stub named `okamoney-web` whose scripts just `cd ../web-frontend && yarn dev|build`.
- The actual frontend is a **Vite web app** in `web-frontend/` (`index.html`, `vite.config.js`, `src/`, `public/`).
- `find /app/scratch -maxdepth 3` for `app.json`/`app.config.*` → nothing.

So the EAS publish can never succeed on this source: it is a web (Vite) app, not an Expo mobile app.

## Why this is not a manifest or retry fix
- The `eas-update` script lives in the deployer binary, not in the app's manifest files — I cannot patch it.
- A plain retry re-runs the identical failure.
- Do NOT just drop a stub `app.json` in `frontend/` — a Vite web app has no Metro/Expo bundle, so `eas update` would still fail (or publish garbage) downstream.

## Suggested fix (E1 to decide intent)
Two mutually-exclusive paths depending on what this app is meant to be:

1. If it is a WEB app (most likely — the real code is a Vite SPA in `web-frontend/`): it should be deployed with a WEB/Kubernetes frontend template, NOT the Expo EAS template `expo_mongo_base_image_eas`. The EAS OTA lane does not belong in this deploy. This is a template-selection change.

2. If it is genuinely meant to be an Expo MOBILE app: the repo must contain a real Expo project under `frontend/` — an `app.json`/`app.config.js` plus `expo` + React Native dependencies and Expo entry code. That does not exist today and would be a substantial build-out, not a config tweak.

Recommendation: confirm the intended target (web vs mobile). Given the source is a Vite web SPA, path 1 (correct the template to a web deployment) is the fix.

## Not reproduced end-to-end
The `eas-update` lane itself cannot be run in the eph sandbox (it needs EXPO_TOKEN and the deployer's baked script). The root cause is established from the Cloud Build log error plus direct source inspection — both unambiguous.
